# Integration Plan: Paperclip + OpenClaw + Scrapling

> **Goal:** Replace ~5,000 lines of custom governance, workflow, and orchestration code with Paperclip as the management layer. Keep OpenClaw as agent runtime, LiteLLM for model routing, Caddy for auth/proxy, Scrapling for scraping.

---

## Phase 1: Add Paperclip Service (No Removals)

**What:** Add Paperclip alongside existing services. Nothing breaks — old code still runs.

### 1a. Docker Compose Changes

Add to `docker-compose.yml`:

```yaml
  paperclip:
    image: ghcr.io/paperclipai/paperclip:latest  # or build from source
    container_name: paperclip
    restart: unless-stopped
    depends_on:
      paperclip-db:
        condition: service_healthy
    environment:
      - DATABASE_URL=postgresql://paperclip:${PAPERCLIP_DB_PASSWORD}@paperclip-db:5432/paperclip
      - PORT=3100
      - SERVE_UI=true
      - PAPERCLIP_DEPLOYMENT_MODE=authenticated
      - PAPERCLIP_DEPLOYMENT_EXPOSURE=private
      - PAPERCLIP_PUBLIC_URL=https://in-fused.org/paperclip
      - BETTER_AUTH_SECRET=${BETTER_AUTH_SECRET}
    volumes:
      - paperclip-data:/paperclip
    networks:
      - ai-hub-network
    deploy:
      resources:
        limits:
          memory: 256M

  paperclip-db:
    image: postgres:17-alpine
    container_name: paperclip-db
    restart: unless-stopped
    environment:
      POSTGRES_USER: paperclip
      POSTGRES_PASSWORD: ${PAPERCLIP_DB_PASSWORD}
      POSTGRES_DB: paperclip
    volumes:
      - paperclip-pgdata:/var/lib/postgresql/data
    networks:
      - ai-hub-network
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U paperclip"]
      interval: 2s
      timeout: 5s
      retries: 30
    deploy:
      resources:
        limits:
          memory: 128M
```

New volumes: `paperclip-data`, `paperclip-pgdata`
New env vars: `PAPERCLIP_DB_PASSWORD` (auto-generated), `BETTER_AUTH_SECRET` (auto-generated)

**Memory impact:** +384M (256M Paperclip + 128M Postgres) → total ~3.2GB. Fits in 2GB RAM + 4GB swap on EC2 t3.small.

### 1b. Caddyfile Changes

Add Paperclip route (behind existing cookie auth):

```
handle_path /paperclip/* {
    @authed {
        header Cookie *mc_oc={$WORKSPACE_PASS_SHA256}*
    }
    handle @authed {
        reverse_proxy paperclip:3100 {
            flush_interval -1
        }
    }
    handle {
        rewrite * /workspace/auth.html
        root * /workspace
        file_server
    }
}
```

### 1c. New Env Vars in `.env`

```
PAPERCLIP_DB_PASSWORD=<auto-generated>
BETTER_AUTH_SECRET=<auto-generated>
```

Add generation to `deploy.sh` (same pattern as existing `DB_PASSWORD`).

## Phase 2: Configure Paperclip ↔ OpenClaw

**What:** Register OpenClaw agents in Paperclip using the built-in `openclaw_gateway` adapter (added in v0.3.0). Paperclip sends heartbeats → OpenClaw agents wake up and do work.

### 2a. OpenClaw Gateway Adapter (BUILT-IN)

Paperclip has a native `openclaw_gateway` adapter at `packages/adapters/openclaw-gateway/`. No custom bridge needed.

Each agent gets registered with `adapterType: "openclaw_gateway"` and config:

```json
{
  "adapterType": "openclaw_gateway",
  "adapterConfig": {
    "gatewayUrl": "http://openclaw:18789",
    "headers": {
      "x-openclaw-token": "<OPENCLAW_PASSWORD value>"
    }
  }
}
```

**Known bug ([openclaw/openclaw#44493](https://github.com/openclaw/openclaw/issues/44493)):** The `x-openclaw-token` header is NOT auto-populated during "Hire Agent" flow. Workaround — patch via SQL after agent creation:

```sql
UPDATE agents
SET adapter_config = adapter_config ||
  '{"headers": {"x-openclaw-token": "<token>"}}'::jsonb
WHERE adapter_type = 'openclaw_gateway';
```

Or use tokenized URL: `http://openclaw:18789/#token=<gateway-token>`

**How heartbeats work:** Paperclip uses "fire-and-forget" mode for OpenClaw — it pings the agent to wake up, agent calls back to Paperclip for context. This replaces our auto-kickoff.js and inbox-check cron system.

**Adapter uses SSE streaming** (not raw WebSocket like our current openclaw-client.js). This is Paperclip's own protocol — Mission Control chat still uses our existing WS client unchanged.

**Compatibility with our setup:** Already have `dangerouslyDisableDeviceAuth=true` + `allowInsecureAuth=true` + Docker bridge networking. Just need to expose `OPENCLAW_PASSWORD` as the gateway token.

### 2b. Agent Registration

Register all 8 agents in Paperclip with:
- Name, role, team assignment
- Model assignment (maps to LiteLLM aliases)
- Monthly budget cap (all free → $0, with DeepSeek fallback cap)
- Tool access restrictions (same deny lists as current TOOL_RESTRICTIONS)
- Adapter config pointing to OpenClaw

### 2c. Goal/Task Structure

Current 2-team hierarchy maps to Paperclip's org chart:
- **Company:** in-fused.org
- **Team: Core** — Lead (CEO), CodeCraft, Scout, Scribe
- **Team: Platform** — Ops Lead (CTO), Builder, Sentinel, Chronicler

Paperclip's goal system replaces our custom governance:
- Goals → high-level objectives (set by owner)
- Tasks → specific work items (created by leads, assigned to specialists)
- Budget enforcement → replaces our tier system

## Phase 4: Rebind Mission Control UI to Paperclip

**What:** Mission Control becomes a thin client that reads from Paperclip's API instead of custom stores.

### What changes in the UI:

| View | Current Source | New Source |
|------|---------------|------------|
| Dashboard stats | Custom governance store + polling | Paperclip REST API (agent status, task counts) |
| Teams/Leaderboard | governance.getLeaderboard() | Paperclip API (agent scores, budgets) |
| Tier badges | governance.metrics[agentId].tier | Paperclip API (agent metadata) |
| Workflow list | localStorage + LiteGraph | Paperclip UI (iframe or redirect to :3100) |
| Staging queue | File polling /workspace/staging/ | Keep as-is (or migrate to Paperclip task output) |
| Activity feed | File polling /workspace/agent-activity/ | Paperclip audit log API |
| Chat | OpenClaw WS (3-tier fallback) | **No change** — chat stays on OpenClaw |

### Two UI approaches:

**Option A — Embed Paperclip UI:**
Add an iframe or link to `/paperclip/` for governance, workflows, and agent management. Keep Mission Control for chat only.

**Option B — API integration:**
Call Paperclip's REST API from Alpine.js stores. Replace governance store with Paperclip data. More work but seamless UX.

**Recommendation: Option A first** — get it working with Paperclip's built-in React UI. Then gradually migrate if needed.

## What MUST NOT Change (Protected Fixes)

These are verified working and critical. Paperclip integration must preserve:

1. **OpenClaw WS handshake** in `openclaw-client.js` — exact auth fields, no device block
2. **Caddy `flush_interval -1`** on every proxy handler — SSE/WS streaming
3. **`tools.profile = 'full'`** in OpenClaw config — agents need coding tools
4. **`compaction.memoryFlush.softThresholdTokens = 50000`** — prevents compaction loop
5. **`OPENCLAW_ALLOW_INSECURE_PRIVATE_WS=1`** — Docker bridge WS
6. **Gateway auth modes** — `dangerouslyDisableDeviceAuth` + `allowInsecureAuth`
7. **LiteLLM fallback chains** — free providers exhausted before paid
8. **Message filtering** (11 regex patterns) — keeps chat clean
9. **Invalid config key deletion** — prevents OpenClaw crash loops
